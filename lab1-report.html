Lab1 工程化改造与单元测试

一、实验目标

  • 完成 FastAPI 项目环境搭建、本地运行与接口调试
  • 解决项目依赖冲突问题，从 requirements 迁移至 Poetry
  • 修复数据库、MinIO 硬编码配置，实现 .env 标准化读取
  • 编写单元测试，建立代码质量保障体系
  • 完成 Git 托管，实现无警告、无报错干净启动

二、实验内容

  • 使用 Conda 创建隔离虚拟环境，避免依赖污染
  • 解决 Pillow、mineru 等依赖版本冲突
  • 完成项目现代化改造，迁移至 Poetry 依赖管理
  • 修复 MySQL、MinIO 硬编码缺陷，统一读取环境变量
  • 编写 18 项单元测试，覆盖配置模块、安全模块

三、遇到的问题

  • 依赖版本冲突严重，项目无法启动
  • 数据库、文件存储配置硬编码，连接失败
  • 密码字段超长导致 bcrypt 加密报错
  • 配置模块存在全局变量风险，环境变量不生效

四、解决方案

  • 使用清华镜像加速，锁定兼容依赖版本
  • 删除所有硬编码，改用 .env 标准化配置
  • 规范密码长度，适配加密算法
  • 修复配置模块逻辑，支持环境变量高优先级覆盖
  • 通过单元测试提前发现安全隐患与架构缺陷

五、实验收获与经验教训

  • 现代 Python 项目必须使用标准化虚拟环境与依赖管理
  • 硬编码是工程化大忌，会导致部署困难、安全性差、不可移植
  • 单元测试不仅验证功能，更能挖掘深层代码缺陷
  • 工程化规范是项目长期可维护、可扩展的基础
